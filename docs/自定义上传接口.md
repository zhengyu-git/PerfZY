# 自定义上传接口

在 PerfZY 的「设置 → 上传设置」填写接收地址和服务签发的 Token。地址保存到本地设置，Token 在本次运行内有效。接收服务无需认证时可留空。使用 Token 连接远程服务时，地址需要 HTTPS。

在「采集记录」点「上传记录」，选择一条已保存的记录，再点「确认上传」。也可从记录行的菜单进入，自动选中该条记录。勾选「同时上传截图」会附带该记录的截图。

## 请求

客户端向接收地址发出一次 POST。接口应直接接受请求，并返回 JSON 回执。

| 请求头 | 值 |
| --- | --- |
| Content-Type | application/json; charset=utf-8 |
| Authorization | Bearer TOKEN，填写 Token 时发送 |
| Idempotency-Key | UTF-8 请求体的 SHA-256 十六进制字符串 |

接收端可按认证账号和 Idempotency-Key 对相同内容去重。这样遇到回执超时，用户手动重传时可以收到同一条记录的回执。编辑后的记录或不同截图选项会生成新的请求体。

请求格式为 perfzy.record.v1。示例使用虚构的设备、应用和采集数据。

    {
      "schema": "perfzy.record.v1",
      "record": {
        "id": "demo-record",
        "name": "测试记录",
        "started_at": "2026-11-12T10:00:00+08:00",
        "duration": 20.0,
        "device": {"platform": "windows", "name": "测试电脑", "os": "Windows 11"},
        "application": {"name": "示例应用"},
        "enabled_metrics": ["fps", "memory"],
        "metrics": {"fps": {"title": "FPS", "unit": "FPS"}, "memory": {"title": "Memory", "unit": "MB"}},
        "scenes": [{"name": "加载", "start": 0.0, "end": 5.0, "color": "#536bb8"}],
        "excluded_intervals": [],
        "timeline_cuts": [],
        "merged_segments": []
      },
      "samples": {"fps": [{"x": 1.0, "y": 60.0}, {"x": 2.0, "y": 58.5}]},
      "screenshots": []
    }

时间字段使用秒，started_at 为记录中的采集时间。samples 按指标键存储实际观测点，x 是相对采集起点的时间，y 是原数值。enabled_metrics 包含当时启用的指标。某项启用了但 samples 中没有相应数据时，服务应按缺失处理。设备的可选字段包括 model、cpu、gpu、memory 和 resolution，移动应用可含 package。

旧记录的空白区间以 excluded_intervals 的 start、end 表示，时间拼接点以 timeline_cuts 的 time、removed_seconds 表示。合并记录通过 merged_segments 的 start、end 和 duration 保留片段边界。

截图元素包含 seconds、content_type 和 data。data 是图片的 Base64，支持 JPEG、PNG 和 WebP，单张最多 16 MiB。服务需要按预期记录时长和截图数量设置接收体积上限。采集时的文件路径、设备序列号、逐帧原始文件和日志独立留在本地。

## 响应

接收成功时返回 HTTP 200、201 或 202 和 JSON。record_id 是 1 至 160 字符的服务端记录编号。服务有可访问的报告时，可返回 HTTP 或 HTTPS 的完整 report_url。

    {"record_id": "server-123", "report_url": "https://example.com/reports/server-123"}

报告仍在生成时，可只返回记录编号。PerfZY 会显示服务已接收，提供报告链接时会显示「打开报告」。上传在后台执行，关闭对话框后可再次点「上传记录」查看本次回执。请求或回执出错时，界面会提示检查连接、授权或接收状态。
